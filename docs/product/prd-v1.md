# Hardwise 产品范围：改版复核主线

## 当前决定（2026-10-27）

用户已选择从整板自动评审转向改版对比。目标是让工程师少在两套导出文件间反复寻找变化，而不是把所有变化判断成正确或错误。旧单版评审保持兼容，已有历史记录不删除；旧全项验收未完成项不会因转向而被标成通过，也不再作为新增比较功能的全部前置条件。

**最小输入**：同一公开设计两个版本的 Cadence PST 文件组（pstxnet.dat、pstxprt.dat、pstchip.dat）或 Telesis 网表，另加 CSV/TSV BOM；不要求规格书、字段批准、AI key 或预先确认全部电压。第一版要求稳定、唯一、精确的位号。重编号暂按位号增删呈现并说明不能自动匹配。

**核心流程**：上传旧版和新版 → 列出器件增删、源属性、引脚网络端点及网络名变化 → 分开查看不能可靠比较的项 → 核对前后来源 → 导出改版清单。

**结果边界**：

- 增删是位号声明变化，不直接证明物理器件增删；BOM 中单独多出的位号不补造为网表器件。
- BOM/网表分别比较；来源冲突和缺行单列，不通过覆盖来源制造确定结论。参数先按文本比较，不猜单位等价或替换兼容性。
- 连接按端点集合比较，不按网名猜。纯网络改名不重复报告为每个引脚重新接线；同名网络端点变化仍应被找到。
- 缺失声明、重复来源及无法匹配都不能归入“没有变化”。直接同网器件只作为复查线索，不宣称完整影响传播。
- 不做整板安全、自动签核或电气正确性判断；无差异只是已比较范围内未观察到差异。

**第一版验收**：一个阻值修改有前后定位；排序/分组变化不制造器件参数变化；器件增删、同名换端点、纯网络改名可区分；重复位号/冲突被拒绝或明确未知；旧数据不被比较请求改写；无 AI、无档案也能操作；离线输出保留相同依据。

**价值验证仍待完成**：用同一个公开设计的前后版本，比较人工整理与工具辅助整理的时间、漏项、假差异和需要作者协助的步骤。不将代码测试数量当作用户价值；若输入准备或结果核对代价超过收益，收缩或停止，不默认扩充知识库。

## 历史 PRD v1.0：单版评审（保留参考，不是当前扩张目标）

2026-10-24｜文档终稿，实施基线建议；未实施、未通过产品验收。

## 1. 产品决定

**为使用 Cadence / OrCAD / Allegro 的硬件工程师，做一个 Layout 前的原理图评审助手：把导出文件变成可核对的检查清单、证据和问题处理记录。** 第一阶段服务你自己及少量同行，以服务器硬件中的供电、控制与基础外围子电路起步。

用户价值不是“AI替我宣布设计正确”，而是少漏掉值得复查的问题、少重复翻资料，并在下次打开时知道哪些问题为什么被处理了。成功是同行愿意再次使用，且能够举出具体帮助。

产品主路径：导入 → 确认解析与电压事实 → 执行限定检查 → 查看依据 → 人工处理 → 导出 → 修改后复查。

## 2. 范围与取舍

| 方案 | 收益与代价 | 决定 |
|---|---|---|
| 修可信性，打通小范围评审闭环 | 覆盖较窄，最快验证是否实用 | 本版采用 |
| 先建完整电源树与AI档案工厂 | 可能增加覆盖，但错误会被放大，难度高 | 分别后置；AI档案限量实验 |
| 做综合EDA/企业平台 | 范围、集成、支持成本远超个人能力 | 不进入路线图承诺 |

**包含**：已有 Cadence 导出链路、BOM关联、人工确认电压/参考地、少量经复核的器件档案、确定性检查、证据定位、问题闭环、本地保存、离线报告。保留 KiCad 作为公开样例和回归输入。

**不包含**：直接读取任意DSN/BRD文件、Cadence实时插件、自动修改原理图、PCB/SI/PI仿真、高速接口全面签核、PLM/BOM管理、器件替代推荐、多人云协作、收费订阅、完整电源树自动推断。不得把“不包含”隐藏成通过。

使用公开或合成设计；遵守项目现有约束，不收集公司内部设计，即使脱敏。参与者的使用授权不等于公开发布授权。

## 3. 核心场景与体验

1. **第一次导入**：用户选择网表/PST文件组和BOM，看到组件、引脚、网络和BOM匹配情况；有错误时可定位到文件及行，不能导入一半却显示成功。
2. **确认事实**：系统列出电压候选、参考地、器件身份及冲突。用户能批量确认已知项，也能保留未知；无须为运行检查填完全部资料。
3. **评审**：用户先看确认违规，再看待补资料和工程提醒。每项说明检查了什么、哪些条件已知、为什么得出结论、去哪复查。
4. **问题闭环**：用户记录已解决、接受风险或误报及理由。关闭服务再打开仍能恢复；设计或规则变化后提示哪些旧结论需要复核。
5. **分享与复查**：导出的报告可以离线读到所有已展示依据与限制；新版本输入与旧版对比，不把所有问题重新堆给用户。

首页主行动是“导入并开始评审”，聊天是问题详情中的辅助动作。产品用语采用“已完成的检查/待补资料/发现的问题”，不用整板“安全”“可投板”结论。

## 4. 输入合同与兼容性

首版以仓库已有 Allegro 文本网表及 PST 导出解析器为基础，BOM优先CSV；Capture pin table是可选增强证据。PDF原理图用于人工查看，不承诺自动理解整张图。

发布支持表必须逐项记录：EDA名称及版本、导出命令/菜单、完整文件组、编码、层级设计处理、BOM表头和成功样例。**当前尚未验证真实Capture版本的完整导出流程；这属于外部试用前的发布门槛，不能预先宣传支持全部Cadence版本。** 首次只承诺实际走通的一条导出路径，其余明确标实验支持。

导入至少显示：解析总量、BOM匹配/缺失/重复/冲突、未解析记录、未映射引脚。保留原始名称与层级限定标识；不把不同层级同名网络、不同组件局部位号意外合并。重复位号或无法确定的引脚映射阻止相关检查，允许其余可判断范围继续。

BOM 属性保留 Value、Description、MPN、封装、额定参数及来源。先读取已存在字段，再做保守提取；冲突进入人工确认，不能默默用“第一个数字”覆盖。导入不能触发外发模型调用。

## 5. 三条独立的状态轴

| 维度 | 状态 | 合同 |
|---|---|---|
| 检查结果 | PASS / FAIL / UNKNOWN / NOT_APPLICABLE | PASS仅代表该检查的必要条件完整且满足；未知不算通过；不适用需理由 |
| 证据性质 | SOURCE_FACT / DERIVED / HYPOTHESIS | 来源事实、规则推导、AI或启发式假设分开；推导须关联输入事实和规则版本 |
| 人工处理 | OPEN / RESOLVED / ACCEPTED_RISK / FALSE_POSITIVE / NEEDS_REVIEW | 人工处理不改写机器结果；接受风险不等于检查通过 |

严重度另设 ERROR/WARNING/INFO，不与未知或人工关闭混为一谈。连通性检查可以PASS，卡片须写“引脚有连接”，不能升级成“复位电路正确”。空检查集显示“未评估”。

覆盖表分别给出候选检查数、适用数、完成数、未知数、不适用数；不支持的器件/规则单列。候选集版本和分母公开，不把所有引脚算进分母制造高覆盖。新版数据合同贯穿CLI、API、页面、导出及评测；旧版未知含义不可直接映射为PASS。

## 6. P0：可信事实与判定

### F01 电压和地

网络名只能产生候选值。诸如 `VBUS_20V`、`USB3P0_D_P`、`PCIE_TX3P3V`不能直接成为可信供电事实。优先使用有来源的显式元数据或人工确认；来源冲突时UNKNOWN。

电压记录包含网络、最小/典型/最大值、参考地/电压域、运行模式、来源和确认状态。用户只填典型值时，不假装具备极限范围。GND/VSS/SGND等名称提示地候选，不自动把机壳地、模拟地、隔离地视为等电位。

首版不自动跨器件传播电压。后续仅在连接、装配状态、工作模式和器件模型均满足时添加有限推导，保留推导路径；禁止泛化跨电感、MOS、开关、转换器或隔离边界。

### F02 电容与电阻

电容耐压按**两端电压差**检查。在共同参考域、同一运行模式且两端范围可信时，用区间端点计算保守最大差值；参考关系未知、缺一端、动态应力未建模时返回UNKNOWN或明确只完成DC子检查。极性和纹波/瞬态能力不能由耐压PASS推断。

电阻功耗在两端DC电压与阻值明确时计算；缺额定功率可以显示估算值，但“功率裕量”必须UNKNOWN。0Ω不能套用除零公式。降额作为板级可配置策略，说明适用器件和工况；未配置时只检查额定值边界，不默认80%普适。

### F03 器件档案与适用条件

档案精确区分厂商、型号后缀、版本和封装。每个用于判定的参数记录单位、引脚/主体、最小/典型/最大、适用条件、文档修订、页码/表格/原文和文件哈希。

器件固有参数与板级策略分开；应用电路推荐不能直接变成无条件硬限值。相对上限（如EN≤VIN）必须表示为关系式，不能压成常数。条件超出规则支持范围时UNKNOWN。

档案状态DRAFT → REVIEWED → READY → RETIRED；READY仅允许经过人工复核的字段参与确定性结论。当前30个档案不因存在于目录就被视为金标准。第一批只选5–10个覆盖试用子电路的高价值型号，已有错误档案先隔离或修正。

### F04 输出边界

所有正式问题以结构化记录输出：对象、检查、输入事实、条件、结论、证据引用、规则版本。位号从当前设计选择/查询，中文相邻文本和五位数字位号也纳入验证；不把DDR4等上下文词一律当位号。

AI可以解释已有问题、提议补资料或产生明确标记的待核假设；不能创建确定性PASS/FAIL、修改档案批准状态或覆盖人工决定。没有工具/证据时，不能输出已检查完毕或直接投板的断言。解析失败、引用失配、模型异常时仍可使用确定性报告。

引用需校验对象、属性、单位和适用条件。对自由文本无法保证完全语义校验，因此禁止“机制上无法编造”的宣传。正式评审结论优先由结构化结果生成，聊天与正式报告分开。

## 7. P0：记录和证据闭环

F05 本地持久化至少保存项目ID、设计修订、输入哈希、检查运行ID、规则/档案版本、确认事实、问题记录和人工决策历史。使用事务写入；异常退出不能留下半条决定。备份/恢复先服务单用户本地场景，不建云账号。

问题身份与事实指纹分开：身份便于关联跨运行问题；指纹包含本项依赖的网络连接、BOM参数、电压确认、档案及规则版本。相关事实变化时旧处理结论标NEEDS_REVIEW，保留历史理由；无关变化不批量清空。问题消失与人工解决分别记录。旧数据缺指纹时要求复核。

F06 每条结论可定位输入文件记录、BOM行、档案参数及规格书页码。离线报告包含可分发的证据摘录、来源链接/哈希、适用条件和缺失项；PDF未随包提供时明确提示。导出不依赖临时服务路径，不自动再分发无授权的完整资料。

## 8. P1：受限的 AI 档案草稿实验

前提是F03合同与人工金标准完成。输入公开PDF及明确器件型号；输出严格schema的草稿和逐字段出处，缺失留空。人工逐项核对后才能升级READY，不能以模型自检取代审批。

实验固定5份PDF，与人工制作同类字段对比：总耗时包含纠错、核对和返工；记录关键字段错误、条件遗漏、引文定位失败。只有在最终人工批准质量不下降且中位总耗时减少至少30%时继续；否则保留人工流程。30%是预设决策门槛，不是已实现收益。评估用资料与提示词调试集按器件家族/文档修订分开。

## 10. 质量、隐私与成功指标

本地模式不外发设计；启用云AI前展示供应商、会发送的数据类别并由用户主动触发。密钥只在服务端，日志/导出不得包含密钥。模型失败不阻断基本闭环。

性能不先承诺任意“大板秒级”：选定公开固定样例、记录机器配置、冷/热运行时间、内存及失败率；第一轮试用前建立基线并检测明显退化。发布必须在目标同行实际使用的Windows环境走通安装/导出/导入/复查；CI通过不等同于这项验收。

初始独立样本：3–5个公开设计/子电路，30–50个正例、负例、边界和未知案例；至少一名独立同行复核标签及依据。冻结留出集，避免同一PDF的近重复跨集。

分别报告：误报数/已核查告警数、检出已标注缺陷数/已知缺陷数、未知比例、各检查族覆盖及分母。漏报只对已标注范围成立，不能称整板召回率。小样本展示原始计数，不包装成行业级准确率。原seeded差分指标改名“非预期新增项”，保留其回归价值。

进入扩大试用的门槛：A01–A14通过；冻结集已知关键反例零回归；误报逐条有归因；没有待处理的误导性PASS缺陷。3位目标同行参加两轮评审，至少2位第二轮实际再次使用，并各指出一个可复核的节省核对步骤或发现问题的案例。记录导入准备、补资料、核查告警和导出的总时间，不能只用机器运行时间报提效。

## 11. 责任与变更

你负责：场景选择、参数与适用条件、人工金标准、同行反馈与发布决定。AI负责：受限范围实现、测试、文档和复现实验。同行负责独立使用与标签复核，不要求他们替项目做免费长期QA。

任何新增检查必须先写适用条件、缺资料行为、正/反/未知案例和证据来源。数据合同变更先评审迁移方案。终稿描述目标行为，不表示现有代码已满足。
