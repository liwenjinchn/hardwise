## 历史工程原件探索补充（2026-10-28）

从个人 DeskPad 工程的两个 Git 修订取出各自留存的 KiCad 网表与 BOM 导出，四份原件均记录提交、Git blob 和 SHA-256。BOM 通过原始 Refs 表头直接导入；只有网表进行任务内的 Telesis 转换。转换副本逐器件属性和网络端点回读一致。这不是原生 Cadence 四文件导出兼容证明，不扩产品网表格式。

该案例确认 3 个测试点位号移除、2 个电容参数变化、3 个 MCU 引脚连接变化。4 条属性记录分别来自两个电容的网表与 BOM，不按记录条数扩大为 4 次独立工程改动。两版各 4 个无连接声明的安装孔共形成 8 个未知项，不能当成电路故障。原始字段与端点集合的复算仅支持该案例，不是外部专家金标。

本轮暴露并修复 Refs 位号表头的导入门槛，同时验证竞争位号声明隔离及分组/表头变化不造假差异。材料在续接任务 `outputs/Hardwise-历史原件改版复核03`。V01 的人工总耗时、实际使用反馈与原生导出路径仍未取得，保持未通过。


## PST 原件接入补充（2026-10-29）

用户明确选择 PST 文件组。比较入口新增原生三文件解析，仍以 CSV/TSV BOM 为配套。每版必须包含 pstxnet.dat、pstxprt.dat、pstchip.dat；不把缺少属性文件伪装成属性删除，不把 primitive 名称推断成 VALUE。PST 与 Telesis 不跨格式比较。

合成 PST 专项覆盖各文件原字节哈希、primitive 参数/封装变化、纯网名变化、同名换端点、缺文件、缺属性、UTF-8 标记/无效编码、未知位号与重复声明、CLI/API/报告一致、八上传角色及体积限制。页面实际多选两组三文件和两份 BOM、运行、下载 JSON/HTML，并核对全部变化和原文件哈希。格式/文件变化须清除结果，旧 Telesis 入口继续回归。

材料在续接任务 `outputs/Hardwise-PST改版接入04`，输入明确标为合成回归例。本轮只证明支持子集的软件链路，不证明三个文件同次导出、实际 Windows/Capture 版本兼容、人工省时或整板电气正确性。V01 仍未通过；旧主线保留分支不变。
