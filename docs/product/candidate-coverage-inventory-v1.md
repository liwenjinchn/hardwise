# 候选目录接入盘点

2026-10-27，基于3828444源码。此盘点不是已完成目录，也不是检查总数。

## 已实证的缺口

- `validation/nets.py`仅在单端网络、没有地名或歧义时输出；`net_naming.py`仅输出命名异常。合成双端GND产生0条结果，改为NO GROUND产生2条。现有分母随问题是否存在而变化，不能由已产生结果反推候选数。证据：任务outputs/Hardwise-候选目录95/finding-only-counterexample.json。
- `connector.py`多个电源脚共用connector_power_voltage、多个地脚共用connector_ground_connectivity；ComponentValidation没有独立端点字段。候选/结果需要结构化instance identity，不能只用refdes+check或靠summary提取脚号。
- `profile_conditions.py`关系检查名仅带target_pin。同目标脚的不同关系必须区分；身份应含关系约束稳定键及目标/供电/参考脚，不以出现顺序冒充身份。
- `component.py`身份冲突会提前返回，未批准档案的scope_result会统一转UNKNOWN；候选枚举不能跟着提前返回而消失。未知topology_family目前返回空列表，需明确“不支持”，不能当零候选已完成。
- `project_index.py`无档案/非通用被动件为manual_rows；不支持组件要单列，不能为未知功能发明任意条规则。

静态AST扫描发现87处带check关键字的调用，其中47处为字面量，40处为常量、模板或转发变量。此数是源码调用点，不是87条规则：重复分支、辅助函数转发、动态端点必须进一步归并；PinValidation不带check，未包含在该扫描内。原始路径、行号、表达式和文件哈希在check-producer-inventory.json。

## 接入映射

| 范围 | 候选枚举依据 | 输出匹配与缺口 |
|---|---|---|
| 项目输入/身份 | 设计与BOM原声明、身份冲突 | 独立资格/阻断项；不猜被阻断对象的功能 |
| 档案批准 | 每个实际匹配档案的器件 | 正常批准也需明确执行记录；未批准保留未知 |
| 档案引脚 | 档案定义的每个脚与类别 | pin_number；连接与电压的复合判断需显式作用域 |
| 关系式 | 每条关系的结构化约束键 | 现有target_pin检查名不足以唯一绑定 |
| 通用阻容感磁珠 | 识别家族、实际端点及固定族规则 | 端点检查与值/额定/封装/应力分别映射 |
| 10类拓扑 | 家族、档案pin配置、必要外围关系 | 动态端点/角色实例；保留缺pin/连接隔离导致的UNKNOWN |
| 网络连接 | 每个观察到的网络及项目地名检查 | 正常分支目前不输出，需新增明确执行结果 |
| 网络命名 | 每个观察到的网名、命名政策及差分适用范围 | 不符合差分形式有明确不适用依据；正常命名不能从分母消失 |
| 未支持对象 | 未匹配或未实现家族及原因 | 单列缺口；不制造虚假工程检查候选 |

下一步先建立候选身份与结果关联不变量，再按此表接入全部范围。只接通用被动件或只收集已有check名字，均不足以关闭PRD覆盖要求。
