# 人工处理状态合同

2026-10-25，用户已选择：旧接受/豁免保留为旧版处理，新决定明确选择接受风险或误报。

Goal / Context / Constraints / Done when:

- Goal：在问题清单、持久日志和交接资料中区分接受风险、误报和已解决。
- Context：旧 accepted/waived 的含义不足以可靠推断新分类；不能用重命名伪造历史判断。
- Constraints：保留原始状态码、理由、时间和追加事件；人工决定不改写机器结果、规则或档案。不额外要求旧决定复核，既有输入/依赖失效逻辑仍适用。
- Done when：新旧状态可共存；新值重启、导出、离线读取和受管理项目备份恢复后含义一致；相关输入变化保留 previous_status 和原理由；无新输入变动不制造迁移事件。

| API/持久化值 | 页面名称 | 含义 |
|---|---|---|
| open | 待处理 | 当前未关闭；重新打开会保留原有事件 |
| accepted_risk | 接受风险 | 人工仍认可问题，但接受其风险，须有理由 |
| false_positive | 误报 | 人工判断此项不适用或判断有误，须有理由 |
| resolved | 已解决 | 人工声明已处理，须有理由；机器结果仍独立 |
| needs_review | 需复核 | 输入/评审依据变化派生，不能通过请求直接写入 |
| accepted | 旧版接受 | 原始含义保留，不自动当作接受风险 |
| waived | 旧版豁免 | 原始含义保留，不自动当作误报 |

白色页面仅提供新分类和解决/重开按钮，问题卡片与历史共用显示名称。旧 accepted/waived 仅允许读取；新写入请求使用这两个值或派生 needs_review 会返回422且不改日志/当前状态，旧页面须重新加载后选择明确的新分类。没有 API 静默别名转换。新旧关闭状态均须理由。CSV、EDA批注和JSON保留明确状态码；Markdown同时列出代码与名称。摘要新增 accepted_risk/false_positive 计数，旧 accepted/waived 计数只数旧记录，需复核独立计数，不计入任一关闭类别。旧摘要缺新字段时模型默认0，不将旧计数并入新类。

SQLite schema仍为v2，不重写历史，不对旧记录批量UPDATE，也不因升级人工状态就改依赖指纹。输入变化仍由既有指纹合同派生需复核，previous_status可保存新旧任一原值；重新决定写入新事件。离线报告保持只读，不自动重分类。

**兼容边界**：旧版程序不认识新状态值，不能承诺降级读取。独立旧/新源码进程验证：新程序重开旧记录时状态/事件不变；写入新值后旧程序拒绝解析，状态、事件、运行和版本头表均未被该失败改写。保留升级前的完整项目备份；不要把同一SQLite schema版本当作旧程序能理解所有新业务值。完整项目ZIP和历史JSON同样需要理解新值的程序。

这些是人工工作流声明，不是工程准确率或人工批准质量的证明；误报标记不能自动训练规则、删除机器发现或批准器件档案。
