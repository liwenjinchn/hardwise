# Hardwise Roadmap v1.0

2026-10-24｜配套[PRD](prd-v1.md)与[评审取舍](review-comparison.md)。本路线图是待实施计划，不是完成记录。

## 1. 推进原则

**先让结论可信，再让闭环可用，然后用真实重复使用决定扩展。** 复用现有解析、规则、工作台和测试体系，不推倒重写。首轮只交付一条经过验证的Cadence导出路径和少量检查。

下面的工时是范围预算，含AI辅助开发与人工复核，不是报价或承诺。按个人每周8–12小时投入，可信性与可用性阶段约需7–16周；实际受复核难度和同行空闲影响。每阶段先用首个任务校准，再决定是否缩小范围。两周可以做一个小验证包，不能等同于完整产品。

## 2. 阶段与放行条件

| 阶段 | 目标与范围 | 建议投入 | 放行证据 |
|---|---|---|---|
| M0 冻结合同与样本 | 对齐状态轴、输入支持范围；复核5–10个高价值档案；组织独立标注 | 12–20小时 | 字段合同、迁移方案、样本清单；错误档案隔离；初始反例可复现 |
| M1 消除误导性结论 | UNKNOWN语义贯穿全链；电压/参考地确认；两端应力；条件参数；输出约束 | 36–60小时 | PRD A01–A08/A14通过；UI/CLI/导出一致；关键反例零回归 |
| M2 完成可用闭环 | 持久化、指纹失效、导入诊断、离线报告、Windows实际导入演练 | 28–44小时 | A09–A13通过；一条真实Cadence导出路径可复现；30–50案例结果公开可查 |
| M3 同行两轮试用 | 3位工程师；3–5个公开设计/子电路；每轮只修主要阻碍 | 主动工作12–20小时，另留2–4周反馈窗口 | 至少2位第二轮再次使用；具体价值案例与总耗时记录；决定继续/收缩 |
| E1 AI档案草稿实验 | 5份PDF，逐字段引用与人工批准；不阻塞M3 | 上限12–20小时 | 同质量下人工总耗时中位数减少≥30%才继续 |

依赖：M0 → M1 → M2 → M3。M0时即可约试用同行和确认EDA版本；M1期间整理操作指南与公开样例。E1只在M0档案合同及金标准稳定之后启动，优先安排在M3反馈等待期；个人精力不足就跳过。

任何阶段发现新的误导性PASS，先暂停扩大试用并回到M1修正。纯展示细节可以进入待办，不应阻断已经可靠的基础闭环。

每个修改包先列具体行为与验收，再实现。正确性修改必须有击中原错误的回归用例；同时执行项目要求的pytest/ruff及受影响前端检查。mock模型测试只证明边界与流程；若宣传真实模型体验，单独记录真实服务版本、输入、费用和结果，不能以mock代替。

## 4. 第一周从哪里开始

以约10小时为首个工作包，不承诺一周完成M0：

1. 约2小时：你复核XL1509及电容±12 V案例，写清“已知什么、未知什么、应判断什么”。
2. 约3小时：AI提出状态合同与迁移样例；你只审核用户可见含义和风险，不必逐行审代码。
3. 约3小时：把5–8个关键反例变成会失败的回归用例，记录当前输出；不同时增加规则家族。
4. 约2小时：你确认首位同行使用的Capture/OrCAD版本及可公开样例，约一次从导出到报告的演练。

下一工作包才实施状态合同及端电压检查。原因是先统一“未知如何呈现”，否则后端修了PASS，前端或报告仍可能把未知当成功。

## 5. 试用怎么做才有判别力

每轮让同行独立完成导入、处理一个告警、解释一项未知、保存重开和导出。记录在哪一步需要作者救场，而非只收“界面挺好”的评价。

选已独立标注的相近难度子电路，一组按原流程，一组用工具；尽量交叉顺序，注明学习效应。样本小，先看每人变化和具体步骤，不宣称统计显著。记录四类时间：准备输入、补事实、核查告警、整理报告；额外收集误报导致的返工。

试用结束回答：哪些提示真正改变了行动？哪些资料确认比人工更麻烦？停用原因是导入、误报、覆盖，还是场景本身没有价值？是否愿意自己再次运行？

## 6. 扩展和停止规则

| 观察 | 下一步 |
|---|---|
| 主要流失发生在导出/安装 | 优先教程、导入诊断或打包；不扩规则 |
| 主要返工来自误报/缺条件 | 缩小支持范围，修证据与条件；不扩档案数量 |
| 基础闭环有价值，但常用型号缺失 | 依据真实请求扩5–10个型号；评估E1，不追求目录数字 |
| 反复卡在确认电压、且图模型足够明确 | 对一个受限拓扑试电压传播；单独PRD/反例/人工确认 |
| ≥2位重复使用且反馈稳定 | 扩到更多公开设计/同行；增加下一类高频检查 |
| 两轮后无人再次使用或总工作量明显增加 | 暂停功能开发，缩到最有价值的一项检查或保留个人工具 |
| 有明确付费需求且愿意持续投入 | 另做商业化研究；不自动启动企业部署、权限、销售与订阅 |

本路线图不承诺本地大模型、国产替代、pin-to-pin替换、高速规则大全、完整电源树、知识图谱平台。只有反复出现的真实需求才触发下一份PRD。

## 7. 每阶段交付与复盘

每个里程碑交付：可运行版本与提交号、支持输入、验收记录、独立样本结果、已知限制及未修问题。将本次实际遇到的规则/档案问题写入项目现有learning log；永久约束只放AGENTS，阶段进度不塞入永久规则。

本轮仅交付计划及补充证据，没有修改产品仓库、运行数据库迁移或提交PR。下一步实施应从T01/T02的最小工作包开始。
