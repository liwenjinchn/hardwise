# 人工复核与两轮试用操作包

2026-10-25。状态：仅准备材料，人工批准、独立标签、真实试用均未取得。配套PRD §10及Roadmap M0/T09/M3/T10；不自动发邀请，不触碰运行时档案，不改变任何放行门槛。

## 先取得什么

1. 用户确认拟试用的公开/合成子电路和首批器件范围。不得提供公司内部设计，即使脱敏；参与试用不等于同意公开个人信息或结果。
2. 一名独立同行核对标签及工程依据，三名目标工程师参加实际使用。可以用参与者代号，保留真实记录的可核对来源，不由AI编造人员或签字。
3. 当前只有macOS，可先做限定本机复核。Windows/Cadence导出路径和安装演练仍须对应操作者及目标机记录；不能由此表或macOS试用替代。

## 档案逐字段复核

已有候选源为 `data/profile_reviews/first_subset_v1.json`，5份244字段；操作说明见[首批档案候选](first-profile-review-subset-v1.md)。本次任务输出Hardwise-人工验收准备50的“档案逐字段待审.csv”将每项固定值、JSON Pointer、原档案SHA、候选手册/修订/页码、AI初筛意见和人工待填栏展开。244项已逐项读取原JSON核对值和定位；5份原文件哈希均匹配，人工决定和独立复核栏全部空白，`preparation-proof.json`保留转换证据。原始候选JSON才是固定输入，CSV不是运行时导入文件。

主审逐项核对：确切厂商/后缀/封装、单位与统计性质、绝对额定或推荐工作、温度/负载/运行条件、实际采用PDF版本和字节哈希、页码/表格/可定位原文。候选来源空哈希保持空，不能把链接当已取得字节。`ai_triage_status`是既有AI初筛，不是人的结论。发现冲突写出更正建议、理由和依据；未确定保留待复核，不能为了填满表强行批准。

填写 `human_decision`（批准该字段/拒绝/需补资料）、`human_reviewer`、`human_reviewed_at`以及对应条件/来源。独立抽查者填写自己的观察和时间。整份档案不是因为部分字段批准就READY；后续仍须按批准的字段/生命周期合同实现，修正原文件后哈希变化必须重新绑定，不能把旧批准套到新文件。当前材料不会授予运行时READY。

## 独立样本与留出集

使用[样本清单模板](acceptance-templates/sample-registry.csv)登记3–5个公开设计/子电路，记录许可、真实导出版本/命令、完整输入及SHA、器件身份/文档家族和开发暴露情况。尚无独立确认的设计选择，不预填现有fixture当留出集。

使用[标签模板](acceptance-templates/case-labels.csv)逐条记录30–50个正例、负例、边界和未知案例。记录检查族/对象、适用条件、必需事实、预期PASS/FAIL/UNKNOWN/NOT_APPLICABLE、严重度、理由及来源版本/页码/哈希。标签作者先按资料写判断，独立同行在未看Hardwise当前结果时核对；有分歧先记录再裁定。没有标签的空行是未完成，不是UNKNOWN标签；UNKNOWN必须写清缺失什么。

先固定清单/文件/标签的实际字节及SHA、审核人和时间，再运行拟验版本；修改输入或标签形成新修订，保留旧记录。开发/调试与留出按器件家族、文档修订及近重复来源检查泄漏；如果所有材料都已用于调试，就明确没有可用独立留出，不将其重新命名成留出。独立复核不等于未暴露的留出，两者分别记。现有eval/manifest.yaml明示pseudo-gold，保留回归价值，不计入独立标签完成数。

## 两轮实际任务

使用[会话记录模板](acceptance-templates/trial-sessions.csv)，每人每轮分别记录一次真实操作；任何未实际发生的任务保持空/未观察，不预填成功。每轮至少独立完成：导入；解释一项UNKNOWN缺失前提；处理一项问题并给出理由；保存、停止服务、按项目ID重开并核对；导出、停止服务、离线查看理由/覆盖边界/缺原文。按需下载备份并恢复独立副本，记录原项目未被替换。

不要在关键步骤直接代操作；必须救场时记录环节、帮助内容及恢复方式。记录错误、误报返工与未覆盖项，不只收主观好评。第二轮必须有实际操作和时间记录，“愿意再用”不算回用；至少2人第二轮真实再次使用。每位给出一个可复查的节省核对步骤或发现问题案例，关联输入修订/问题和依据，不从满意度推出提效。

比较相近难度子电路的原流程与Hardwise流程，尽量交叉顺序，记录学习效应、设备、版本和作者帮助。分别计输入准备、补事实、核查告警、整理/导出报告四类时间，另记返工和总墙钟时间。说明返工是否已包含于四类阶段及是否有重叠/中断，不能机械相加双算；未计时保持空，不填0。CLI运行时间不能代替人的总工作时间。规模小，只展示每人的原始记录和可解释变化，不宣称统计显著。

## 结果怎样算

用[逐项归因模板](acceptance-templates/finding-attribution.csv)关联冻结标签、机器输出和实际核查结果。保留所有未核查与争议项，不能从分母中悄悄丢弃或直接算真阳性。

| 指标 | 可报告范围 | 不允许的替代 |
|---|---|---|
| 误报 | 人工确定误报数 / 已完成核查的告警数，并单列未核查/争议数 | 不把未核查告警视为正确；不把接受风险等同误报或机器PASS |
| 检出 | 检出的已标注缺陷数 / 该冻结范围已知缺陷数；逐条关联对象和检查 | 不称整板召回率；漏检不能仅凭没有告警推断不存在缺陷 |
| 未知/覆盖 | 各检查族已生成记录的原始PASS/FAIL/UNKNOWN/N/A计数；候选分母缺失则写缺失 | 不把引脚数或已有输出数冒充全板候选检查集合 |
| 使用价值 | 每人两流程四类时间、返工/帮助、回用事实和具体案例 | 不从机器耗时或“愿意使用”推断实际节省/回用 |

分母为0或缺记录时写未评估，不显示0%误报/100%检出。一个缺陷被多个检查发现时先按冻结的缺陷对象归并再计缺陷，不把告警条数当缺陷数。独立标签、机器结果和人工处理状态保留不同列，不能互相覆盖。

## 放行仍需什么

所有A01–A14和PRD明确要求的支持/隐私/证据合同满足；冻结集关键反例零回归、误报逐条归因、没有待处理误导性PASS；真实Windows/Cadence路线留证；三人两轮且至少两人回用及价值/总耗时记录。M0–M3分别按原路线图审核，最终用户决定是否继续/收缩。T11/E1有前提且可选，未被此操作包新增成必需门槛。

本操作包不表示上述任何观察已发生。空模板不能作为验收结果；完成表格也需核对实际输入、操作者和原始记录。已知软件缺口见[完整台账](full-acceptance-v1.md)，不得把它们藏在等待人工的理由下。
