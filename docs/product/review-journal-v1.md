# 本地评审日志 v1

2026-10-24。实现记录；不是完整项目文件或 A09/A10 放行证明。

## 使用

```bash
PYTHONPATH=src uv run hardwise serve-workbench \
  tests/fixtures/allegro/l78_regulator.net \
  tests/fixtures/allegro/l78_regulator_bom.csv \
  --fake-ai --review-db data/reviews/public-demo.sqlite
```

保留原输入文件及路径、profiles 目录和相同日志路径，再启动命令可恢复该来源项目的人工决定。未指定 `--review-db` 时仍使用服务内存；界面明确显示不会跨服务退出恢复。SQLite 文件及其事务侧文件已加入 Git 忽略规则。

此文件保存人工决定、追加事件、运行 ID、任务快照、语义输入指纹及新运行的输入/档案/规则清单。它**不复制网表、BOM、上传文件组或完整原始资料**，因此还不能作为可搬迁的完整项目包。网页上传使用的临时源目录仍会在服务结束时清理；不能据此承诺上传项目的完整跨重启恢复。

## 合同

- `stable_key` 关联问题身份；依赖指纹判断旧处理是否仍适用；二者分开。
- 源路径身份产生项目 ID；每次启动/重跑产生运行 ID。不同来源项目在同一文件中隔离。
- 当前状态、事件与运行快照在同一事务写入；写入失败不发布半条决定，也不改变原内存状态。
- 记录消失时从当前列表撤下，保留 `disappeared` 历史；不伪造成工程师手工解决。
- 指纹变化或旧记录缺指纹时显示 `needs_review`，保留旧状态、理由和旧/当前指纹。事实后来改回也不会自动恢复旧豁免。
- 人工决定不修改机器结果、严重度或器件档案。
- 本地文件模式写入须携带当前 `expected_run_id`。旧页面返回 409；未提供运行 ID 返回 400。当前白色 UI 自动携带运行 ID。兼容的内存 API 可省略该字段；提供时仍验证。
- 同一日志的旧进程写入者被版本检查拒绝，保存决定和重跑均返回 409，避免覆盖另一进程已提交的状态；原服务的活动运行保持不变，需重新启动以加载当前日志。面向本地单用户，不宣称多人协作。
- 不识别的未来/外部数据库格式保留原文件并报错，不自动覆盖。无指纹的已知旧决定只能恢复成需复核。
- 导入激活失败时恢复原评审命名空间；候选分析运行不等于已成功激活的新项目。

白色新版入口：**问题清单 → 查看处理历史**。每页 20 条，显示人工更新、输入变化需复核和从当前列表撤下，保留原理由和事件时间；可展开问题标识、事件所属运行和旧/事件时输入指纹。撤下不表示人工解决。历史问题仍在当前列表时，标题明确标为“当前对应问题”，不冒充历史时刻标题。无当前对应项时仍保留原问题键和理由。

历史接口：`GET /api/workbench/review-decisions/history?limit=100&offset=0&expected_project_id=<project>`。响应包含 `project_id`、当前服务 `run_id`、`total`、`limit`、`offset`、`events`；既有 events 字段保留。limit 为 1–1000，offset 非负；当前 UI 传入项目 ID，项目切换后旧请求返回 409。SQLite 页和总量在同一读事务读取。内存模式也可查看本次服务历史，仍不跨退出恢复。

历史按最新在前分页；新增事件后可刷新回到第一页，不声明跨分页浏览时冻结了全局历史。页面在新运行、项目或处理次数变化时重新读取，并忽略已卸载页面的迟到响应。读取失败可重试，不写入人工决定。离线快照尚未嵌入完整历史，明确提示打开本地服务，不伪装成“没有记录”。既有服务进程需重启以加载新接口；示例服务只绑定本机。

## 依赖边界

已审查的局部数值规则按**规则名及版本白名单**选择组件级依赖：相关组件/引脚、该组件档案、当前模式、端点和参考网络的电压记录，以及机器评估字段。通用引脚的现有版本也采用组件级范围。来源坐标的纯变化不当作电气事实变化；运行时间、任务排序号与其他人工决定不参与指纹。

未登记的新规则或新版本，以及拓扑/辅助任务，采用项目语义快照兜底，不根据名字前缀猜测依赖。该兜底可能使无关的语义变化也要求复核；这是待细化的覆盖缺口。组件级范围也比单参数依赖更宽，不能宣称所有问题均已精确失效。规则实现变化必须更新声明版本及依赖合同；不声称能自动发现任意未升版本的源码改动。

## 运行输入与版本清单

`GET /api/workbench/review-runs/{run_id}/provenance?expected_project_id=<project>` 返回可下载的 JSON，包含捕获时间、原始字节 SHA-256/大小/逻辑及解析路径/读取角色、实际绑定的档案模型快照及模型哈希、组件绑定、已发出检查的规则名/声明版本/记录数、Python 与包版本。清单与运行/状态/事件在现有 SQLite 事务中一起保存，不升级日志格式。内存模式仍只保留本次服务数据。跨活动项目请求返回 404，携带过期项目 ID 返回 409；存储或清单损坏返回 503。旧运行返回 not_recorded，不从当前磁盘倒推历史。白色页面的问题清单及导出页可下载本次清单，处理历史每条记录的追溯详情可下载该次运行清单。新 --ai-snapshot HTML 内嵌清单，不依赖本地服务即可下载。

输入摘要在已登记的实际读取点采集：Telesis/PST、BOM（含 XLSX 原始压缩文件）、档案、已确认电压事实、文档索引、引脚表、风险提示、评审包和原流程已计算哈希的评审附件。多次读取同源不同字节、已读取文件暂时消失或构建完成前内容/符号链接目标变化，都会拒绝发布候选上下文。解析失败的可选候选若已被读取，也可能列在清单中；文件集合是读取集合，不代表全都参与检查。实际使用档案由 profile_bindings 单独给出。

这不是文件系统的原子快照：不监控目录成员变化或未观察到的改动后恢复；不归档原文件，不自动读取文档索引指向的所有 PDF，不证明附件内容真实性，也不证明已审核档案。档案模型哈希与源文件字节哈希用途不同；非有限浮点以显式标签保存，避免变成 null。规则版本是生产者声明，不是完整源码/二进制哈希或可重现运行保证；实现变更仍须维护声明版本。输入原始哈希不直接替代语义依赖指纹，因此测试中的 BOM 空白变化会生成不同原始哈希，同时保留原局部豁免。


### 白色页面与离线交接

下载 JSON：服务模式保留真实 project_id/run_id/status/reason，旧运行缺失时下载 not_recorded 说明并在页面提示，不拿当前运行替换。读取失败显示错误，可重试；响应所属项目/运行不符则拒绝下载。组件在项目、运行或页面切换后丢弃迟到请求。下载只读，不改人工决定和机器检查。

离线导出沿用单文件快照结构，run_provenance 是兼容的可选字段；下载以 origin=offline_export 和 exported_at 标识本次导出，保留导出上下文捕获的原始读取清单，不虚构服务运行 ID，也不关联任何持久日志事件。旧 HTML 缺字段时明确提示重新导出，不访问静态服务器补取；历史运行请求不会被当前离线清单替代。完整历史仍未嵌入，原文件/PDF与可搬迁项目归档仍未完成。
