# 本地评审日志 v1

2026-10-24。实现记录；不是完整项目文件或 A09/A10 放行证明。

## 使用

```bash
PYTHONPATH=src uv run hardwise serve-workbench \
  tests/fixtures/allegro/l78_regulator.net \
  tests/fixtures/allegro/l78_regulator_bom.csv \
  --fake-ai --review-db data/reviews/public-demo.sqlite
```

保留原输入文件及路径、profiles 目录和相同日志路径，再启动命令可恢复该来源项目的人工决定。未指定 `--review-db` 时仍使用服务内存；界面明确显示不会跨服务退出恢复。SQLite 文件及其事务侧文件已加入 Git 忽略规则。

此文件保存人工决定、追加事件、运行 ID、任务快照及语义输入指纹。它**不复制网表、BOM、上传文件组或完整原始资料**，因此还不能作为可搬迁的完整项目包。网页上传使用的临时源目录仍会在服务结束时清理；不能据此承诺上传项目的完整跨重启恢复。

## 合同

- `stable_key` 关联问题身份；依赖指纹判断旧处理是否仍适用；二者分开。
- 源路径身份产生项目 ID；每次启动/重跑产生运行 ID。不同来源项目在同一文件中隔离。
- 当前状态、事件与运行快照在同一事务写入；写入失败不发布半条决定，也不改变原内存状态。
- 记录消失时从当前列表撤下，保留 `disappeared` 历史；不伪造成工程师手工解决。
- 指纹变化或旧记录缺指纹时显示 `needs_review`，保留旧状态、理由和旧/当前指纹。事实后来改回也不会自动恢复旧豁免。
- 人工决定不修改机器结果、严重度或器件档案。
- 本地文件模式写入须携带当前 `expected_run_id`。旧页面返回 409；未提供运行 ID 返回 400。当前白色 UI 自动携带运行 ID。兼容的内存 API 可省略该字段；提供时仍验证。
- 同一日志的旧进程写入者被版本检查拒绝，避免覆盖另一进程已提交的状态。面向本地单用户，不宣称多人协作。
- 不识别的未来/外部数据库格式保留原文件并报错，不自动覆盖。无指纹的已知旧决定只能恢复成需复核。
- 导入激活失败时恢复原评审命名空间；候选分析运行不等于已成功激活的新项目。

历史接口：`GET /api/workbench/review-decisions/history?limit=100&offset=0`，按当前来源项目返回事件；`limit` 为 1–1000，`offset` 非负。完整历史还保存在本地日志，不因 UI 只显示当前处理理由而删除。

## 依赖边界

已审查的局部数值规则按**规则名及版本白名单**选择组件级依赖：相关组件/引脚、该组件档案、当前模式、端点和参考网络的电压记录，以及机器评估字段。通用引脚的现有版本也采用组件级范围。来源坐标的纯变化不当作电气事实变化；运行时间、任务排序号与其他人工决定不参与指纹。

未登记的新规则或新版本，以及拓扑/辅助任务，采用项目语义快照兜底，不根据名字前缀猜测依赖。该兜底可能使无关的语义变化也要求复核；这是待细化的覆盖缺口。组件级范围也比单参数依赖更宽，不能宣称所有问题均已精确失效。规则实现变化必须更新声明版本及依赖合同；不声称能自动发现任意未升版本的源码改动。
