# 本地评审日志 v1

2026-10-24 初版，2026-10-25 按当前实现校正。此处区分评审日志、受管理项目和离线报告；不是 A09/A10 或 M2 放行证明。

## 使用

```bash
PYTHONPATH=src uv run hardwise serve-workbench \
  tests/fixtures/allegro/l78_regulator.net \
  tests/fixtures/allegro/l78_regulator_bom.csv \
  --fake-ai --review-db data/reviews/public-demo.sqlite
```

使用原始路径启动时，保留原输入文件及路径、profiles 目录和相同日志路径，再启动命令可恢复该来源项目的人工决定。未指定 `--review-db` 时仍使用服务内存；界面明确显示不会跨服务退出恢复。SQLite 文件及其事务侧文件已加入 Git 忽略规则。

SQLite 保存人工决定、追加事件、运行 ID、任务快照、语义输入指纹及新运行的输入/档案/规则清单。**仅指定 `--review-db` 不等于保存原始输入**：尚未显式保存的上传源仍是临时目录，结束服务后不能依靠日志恢复其原文件。

白色页面“导入 → 保存与重开”可显式保存当前输入。已保存项目的原始字节由相邻 `<日志文件名>.inputs/` 目录持有，SQLite 记录对应项目与版本；已保存输入可在原路径失效后重建。搬迁须保留日志和输入目录，或使用完整项目备份 ZIP；不能只搬 SQLite。保存、重开、独立副本恢复的具体命令与版本边界见 [受管理项目合同](managed-project-v1.md)。不自动收集文档索引指向的外部 PDF。

## 合同

- `stable_key` 关联问题身份；依赖指纹判断旧处理是否仍适用；二者分开。
- 源路径身份产生项目 ID；每次启动/重跑产生运行 ID。不同来源项目在同一文件中隔离。
- 当前状态、事件与运行快照在同一事务写入；写入失败不发布半条决定，也不改变原内存状态。
- 记录消失时从当前列表撤下，保留 `disappeared` 历史；不伪造成工程师手工解决。
- 指纹变化或旧记录缺指纹时显示 `needs_review`，保留旧状态、理由和旧/当前指纹。事实后来改回也不会自动恢复旧豁免。
- 人工决定不修改机器结果、严重度或器件档案。
- 本地文件模式写入须携带当前 `expected_run_id`。旧页面返回 409；未提供运行 ID 返回 400。当前白色 UI 自动携带运行 ID。兼容的内存 API 可省略该字段；提供时仍验证。
- 同一日志的旧进程写入者被版本检查拒绝，保存决定和重跑均返回 409，避免覆盖另一进程已提交的状态；原服务的活动运行保持不变，需重新启动以加载当前日志。面向本地单用户，不宣称多人协作。
- 不识别的未来/外部数据库格式保留原文件并报错，不自动覆盖。无指纹的已知旧决定只能恢复成需复核。
- 导入激活失败时恢复原评审命名空间；候选分析运行不等于已成功激活的新项目。

白色新版入口：**问题清单 → 查看处理历史**。每页 20 条，显示人工更新、输入变化需复核和从当前列表撤下，保留原理由和事件时间；可展开问题标识、事件所属运行和旧/事件时输入指纹。撤下不表示人工解决。历史问题仍在当前列表时，标题明确标为“当前对应问题”，不冒充历史时刻标题。无当前对应项时仍保留原问题键和理由。

历史接口：`GET /api/workbench/review-decisions/history?limit=100&offset=0&expected_project_id=<project>`。响应包含 `project_id`、当前服务 `run_id`、`total`、`limit`、`offset`、`events`；既有 events 字段保留。limit 为 1–1000，offset 非负；当前 UI 传入项目 ID，项目切换后旧请求返回 409。SQLite 页和总量在同一读事务读取。内存模式也可查看本次服务历史，仍不跨退出恢复。

历史按最新在前分页；新增事件后可刷新回到第一页，不声明跨分页浏览时冻结了全局历史。页面在新运行、项目或处理次数变化时重新读取，并忽略已卸载页面的迟到响应。读取失败可重试，不写入人工决定。由当前服务导出的新离线报告可封存当前项目完整历史和历史运行清单，见下文。旧 HTML 或 CLI 独立快照缺少服务日志历史时明确提示不可用，不伪装成“没有记录”。既有服务进程需重启以加载新接口；示例服务只绑定本机。

## 依赖边界

已审查的局部数值规则按**规则名及版本白名单**选择组件级依赖：相关组件/引脚、该组件档案、当前模式、端点和参考网络的电压记录，以及机器评估字段。通用引脚的现有版本也采用组件级范围。来源坐标的纯变化不当作电气事实变化；运行时间、任务排序号与其他人工决定不参与指纹。

四类第2版控制观察（NRST、BOOT0、I²C repeater enable、shift-register clock enable）采用控制脚直接网络邻域，包含实际选中引脚、网络节点、直接邻接器件及端点/参考电压事实。远处独立器件变化可保留决定；相关支路变化触发复核。旧项目快照范围的决定首次升级时要求复核，相同重跑不重复追加同一失效事件。

未登记的新规则或新版本，以及其他拓扑/辅助任务，采用项目语义快照兜底，不根据名字前缀猜测依赖。该兜底可能使无关的语义变化也要求复核；这是待细化的覆盖缺口。组件级范围也比单参数依赖更宽，不能宣称所有问题均已精确失效。规则实现变化必须更新声明版本及依赖合同；不声称能自动发现任意未升版本的源码改动。

## 运行输入与版本清单

`GET /api/workbench/review-runs/{run_id}/provenance?expected_project_id=<project>` 返回可下载的 JSON，包含捕获时间、原始字节 SHA-256/大小/逻辑及解析路径/读取角色、实际绑定的档案模型快照及模型哈希、组件绑定、已发出检查的规则名/声明版本/记录数、Python 与包版本。清单与运行/状态/事件在 SQLite 事务中一起保存。当前日志 schema v2 的受管理目录扩展是增量迁移；v1 旧程序不能打开 v2，回退应使用升级前备份，不能声称支持降级。内存模式仍只保留本次服务数据。跨活动项目请求返回 404，携带过期项目 ID 返回 409；存储或清单损坏返回 503。旧运行返回 not_recorded，不从当前磁盘倒推历史。白色页面的问题清单及导出页可下载本次清单，处理历史每条记录的追溯详情可下载该次运行清单。新 --ai-snapshot HTML 内嵌清单，不依赖本地服务即可下载。

输入摘要在已登记的实际读取点采集：Telesis/PST、BOM（含 XLSX 原始压缩文件）、档案、已确认电压事实、文档索引、引脚表、风险提示、评审包和原流程已计算哈希的评审附件。多次读取同源不同字节、已读取文件暂时消失或构建完成前内容/符号链接目标变化，都会拒绝发布候选上下文。解析失败的可选候选若已被读取，也可能列在清单中；文件集合是读取集合，不代表全都参与检查。实际使用档案由 profile_bindings 单独给出。

输入读取清单不是文件系统的原子快照：不监控目录成员变化或未观察到的改动后恢复；清单本身不归档原文件，不自动读取文档索引指向的所有 PDF，不证明附件内容真实性，也不证明已审核档案。档案模型哈希与源文件字节哈希用途不同；非有限浮点以显式标签保存，避免变成 null。规则版本是生产者声明，不是完整源码/二进制哈希或可重现运行保证；实现变更仍须维护声明版本。当前新运行还声明 `review_dependency_contract=hardwise.review_dependencies.v2`，旧清单缺字段保持 null，不补写历史。输入原始哈希不直接替代语义依赖指纹，因此测试中的 BOM 空白变化会生成不同原始哈希，同时保留原局部豁免。


### 白色页面与离线交接

下载 JSON：服务模式保留真实 project_id/run_id/status/reason，旧运行缺失时下载 not_recorded 说明并在页面提示，不拿当前运行替换。读取失败显示错误，可重试；响应所属项目/运行不符则拒绝下载。组件在项目、运行或页面切换后丢弃迟到请求。下载只读，不改人工决定和机器检查。

服务页面导出调用 `GET /api/workbench/offline-report?expected_project_id=<project>&expected_run_id=<run>`。它只读封存当前项目的决定、完整事件及历史运行清单，并将同一批决定用于详情、CSV 和准备包。SQLite 事件和运行记录来自同一修订快照；过期项目/运行或其他进程写入返回 409，捕获失败返回 503，不交付半份报告。关闭服务后，新单文件报告在本地查看和分页历史、下载对应历史清单；不访问 API，不允许修改人工决定。历史缺清单保留 not_recorded。

CLI `design-validator-ui --ai-snapshot` 仍可独立生成报告，保留其自身输入清单，但没有服务日志的项目/运行与历史。其当前清单下载以 origin=offline_export 和 exported_at 标识；不能拿它代替服务项目历史。旧 HTML 缺相应字段时提示重新导出，不访问静态服务器补取，也不拿当前清单替代旧运行。

报告与可恢复项目 ZIP 是两种交付物。单文件 HTML 不包含完整原始输入或自动随附 PDF；来源核对状态和原文随附状态分别显示，缺原文仍允许导出并列明待核查。完整项目 ZIP 包含已保存的受管理原始输入和日志，外部链接 PDF 不会因本机存在或来源已核对而自动随包。文件存在、哈希匹配与人工工程批准仍是不同证据。
